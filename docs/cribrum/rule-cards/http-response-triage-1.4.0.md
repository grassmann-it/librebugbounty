# HTTP-response triage: candidate 1.4.0

This compatible extension of [candidate 1.3.0](http-response-triage-1.3.0.md)
retains pack schema 2, evidence schema 1, registered detector/output identifiers,
report policy, filters and mail contracts. The candidate requires explicit
selection; shadow remains the default. Rollback restores **1.3.0 code and pack
together**, including its compatible tests and documentation. Neither changing
the pack version nor installing source initiates an inventory reclassification.

## SQL operands and diagnostic boundaries

`sql-triage-v1` accepts bounded balanced parentheses around already supported
Access operands, preserving actual function operands and Access concatenations.
The local complete input, clause boundary and lexical checks still apply. A
damaged reflected URL parameter never acquires an SQL operand relationship merely
because an equals sign precedes it.

Older IIS error pages bound the query expression to the actual adjacent error
message, excluding Browser/Page/Time footer sections. The query-end requirement
is retained. `Characters found after end of SQL statement.` is a JET diagnostic
only with local provider context. It alone supplies no SQL structural indication.
An explicit ODBC SQL Server provider identifies that vendor; missing vendor
evidence remains `unknown`. Yii collation, conversion and binding errors remain
nonstructural even when an input echo and query are present.

A complete appended JSON object can supply its immediate error message, including
the WordPress `data.error.message` shape. JSON decoding is performed once and
mapped to original response spans; it does not recursively decode HTML entities.
The input retains the explicit URL-query decoding transformation. A full probe
in a `near` excerpt may establish `input_in_sql_error`, but without a full
supported query/expression it cannot establish `sql_input_structure_indication`.
Unrelated titles, JSON siblings and incomplete objects do not supply the relation.
Qualified structural indications remain **suspected**, never confirmed SQLi.

## Include wrappers

`file-triage-v1` adds `0 - Failed opening required` titles, exact leaf p/div
diagnostics and bounded blockquote diagnostics with a real numeric badge.
Badge attributes are parsed as actual attributes; `data-class`, attribute text
and later duplicate attributes do not impersonate the effective class. Templates
and example containers cannot supply this new route.

Quotes are decoded once, with exact original diagnostic and target spans.
A doubly encoded title is not repeatedly decoded; a separate complete simply
encoded diagnostic is eligible. Missing operations remain absent. These wrappers
are diagnostic-only, even for fixed paths or a coincident request value; they do
not create LFI/RFI or prove a successful include. The old standalone exact p
fixture deliberately changes from negative to positive; surrounding prose is a
separate negative control.

## Concrete internals and delivered PHP source

`context-triage-v1` adds coherent Java chains without `at`, further .NET method
chains, numbered iPHP chains and individually qualified Yii HTML headers with
method, file and line. Yii language, session dumps, SQLSTATE and product/version
footers are not required. Virtual `iCMS://` paths do not become filesystem paths.
Populated IIS Physical Path rows require an actual detailed-error context.
Documentation markers/rows cannot be borrowed to establish that context.
PHP JSON errors additionally accept exactly type 64. `/is/` and `/hp/` roots
qualify within real diagnostic/frame forms, not as arbitrary slash text.

Delivered unescaped PHP source can produce the existing
`internal_information_exposed` with `detailKind=source_code` when a complete block
of at most **8192 raw bytes** contains a complete function, literal variable
assignments and their actual argument references in `mysql_connect` and
`mysql_select_db`. Parsing is lexical; source is never executed or included.
The existing match cap remains. This narrowly recognizes the observed connection
configuration family, not arbitrary PHP, sessions or credentials.

Escaped code, XML, example/documentation containers (including nested wrappers),
code inside strings/comments, disconnected assignments, isolated names/calls,
incomplete and oversized blocks are counterexamples. These exclusions are local
to the new source/field evidence; genuine diagnostic frames in pre/code, hidden
content or comments can still expose internals.

Source evidence retains unchanged original spans privately. Signal attributes
contain fixed descriptive metadata, not additional copies of source values.
No assertion is made about credential validity, execution or inclusion.

## Consumer acceptance and evidence limits

The [engine acceptance tests](../../../tests/BehaviorEnginePipelineAcceptanceTest.php)
exercise registered engine → stored observation/facts → projection → strict
filters → local report-gen reader/composition. The cross-language acceptance run
requires `RGEN_BEHAVIOR_PATH` pointing to the matching integration consumer;
skipping these tests does not satisfy release acceptance.

- SQL diagnostic-only cases retain their warnings without a SQLi component or
  urgency. Confirmed XSS remains confirmed; a qualified SQLi suspicion is one
  additional component in the same combined report.
- New concrete internals reach disclosure composition. Mixed XSS/disclosure
  cases are excluded from both strict pure scopes. Include diagnostics do not
  invent inclusion suspicion.
- Synthetic source canaries remain visible in authenticated private evidence,
  but absent from attributes, recipient context, controlled paragraphs and the
  complete composed mail. The PoC is unchanged. This tests automatic data
  forwarding with safe author fields; the metadata guard is **not** a general
  secret scanner for arbitrary manually supplied author text.
- Existing challenge/presence/block distinctions and the new relevant block
  review/mail hold remain unchanged. Development instructions, generic failures,
  CAPTCHA presence and Cloudflare Worker1101 cannot invent disclosure or blocks.

Compare Core, frozen 1.3.0 and 1.4.0 on identical immutable bytes, recording full
signals, vendor/parameter relations, original spans, claims, coverage and class
source hashes. Selected private captures through Direct67 are regressions, not
independent holdout or an accuracy estimate; related templates do not count as
independent evidence. Public fixtures are synthetic and contain no private
capture URLs, source values or finding identifiers.

See [contribution guidance](../contributing.md) and [activation/rollback](../activation.md).
No new migration, mail type, model routing or vendor-specific UI is introduced.
GraphQL, infrastructure metadata, CSS IPs, general session/credential detection,
gzip and semantic response completeness remain separate work.
